# 简历 · 岗位匹配度分析器（Resume–JD Matcher）

> 一个把「投简历石沉大海」这个模糊抱怨，变成「哪一句该改、改成什么」的小工具。
> 输入：一份简历（.docx）+ 一份 JD（.txt）
> 输出：匹配度、逐条对照、3 个致命短板、句子级改写建议、面试追问点

---

## 为什么做这个

我在投 AI 产品实习的时候遇到两个具体问题：

1. **改简历没有方向。** 投了没人回，不知道是学校不行、经历不够，还是那句话没写对。
2. **网上那种"AI 改简历"，改出来的东西不是我的。** 它会给我补上"负责过 XX 项目"，面试一问就穿帮。

所以这个工具的定位很克制：**它不改你的简历，它告诉你哪句话该改、为什么。**
最终决定权还在人手上——这是我在设计时做的第一个取舍。

## 快速开始

```bash
# 1. 安装依赖
pip install python-docx openai

# 2. 配置模型（Windows）
setx DEEPSEEK_API_KEY "sk-你的key"
# 重开终端生效

# 3. 跑
python analyzer.py examples/resume.docx examples/jd-sample.txt
```

输出同时在终端打印，并落一份 `report.json`（结构化，后面可以接前端或统计）。

## 三个设计取舍（面试会问）

| 取舍 | 我放弃了什么 | 为什么 |
|---|---|---|
| 不做"总分制" | 放弃了一眼看懂的爽感 | 总分没有行动价值。用户要的是"改哪句"，不是"我 62 分" |
| 不做全自动改写 | 放弃了"一键生成"的卖点 | 模型改写会编造经历，面试一追问就穿帮。风险 > 收益 |
| 强制结构化 JSON | 放弃了直接输出漂亮文案 | 结构化之后才能接工作流、做统计、做 A/B 对比。这是能不能规模化迭代的前提 |

## 提示词设计的四个决定

1. **角色设定给"招聘官"而不是"简历顾问"** —— 顾问会鼓励你，招聘官会筛你。要的是筛人逻辑。
2. **三条纪律写死在 system 里** —— 尤其"没写的就当没有"，这是防幻觉最关键的一句。
3. **每条差距必须给"可直接照抄的改写句"** —— 不给"建议突出XX能力"这种正确的废话。
4. **temperature 0.2** —— 这个任务要的是稳定复现，不是创意。同一份简历跑两次，结论应该基本一致。

## 已知局限（写在前面，比藏着好）

- 只支持 .docx 和 .txt，不支持 PDF（PDF 解析排版错乱太严重，宁可先不做）
- JD 要求超过 15 条时，模型会开始漏掉后面的（长文本衰减）
- 只判断"写了没写"，不判断"写得深不深"——这是下一版要解决的
- 匹配度分数目前是模型主观打分，没有校准。**它适合做相对比较，不适合当绝对标准**
