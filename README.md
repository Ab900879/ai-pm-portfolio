## 项目

### 1. [`resume-jd-matcher/`](./resume-jd-matcher) —— 简历·岗位匹配度分析器

投简历石沉大海，不知道问题在哪儿。做一个工具，把 JD 和简历逐条对照，输出匹配度、3 个致命短板、**可以直接照抄的改写句**。

- 三个设计取舍：不做总分制、不做全自动改写、强制结构化 JSON
- 真实跑通：用我自己的简历跑出 38/100，暴露了"无产品交付物"这个核心短板
- 技术栈：Python · python-docx · DeepSeek API

**面试可讲点**：为什么"不给总分"、"为什么不让 AI 直接改简历"（幻觉风险 > 收益）

---

### 2. [`tech-to-human/`](./tech-to-human) —— 技术语言 → 人话 翻译器

通信背景让我看得懂技术文档，但写出来的东西非技术的人看不懂。做一个三档翻译器：同行版 / 职场版 / 大白版。

- 核心方法论：**只给判据，不给形容词**。"要通俗易懂"模型不知道怎么算达到；"禁止出现任何英文缩写"模型能逐条自查
- 踩过三个坑：通俗被做成删减 / 三档混在一个提示词里 / "用小学生语言"变成幼稚化
- 技术栈：Python · DeepSeek API · 提示词与代码分离

**面试可讲点**：三档约束怎么设计的、为什么档位必须由用户显式指定

### 3. [`prompt-lab/`](./prompt-lab) —— Prompt 迭代实验

同一份素材，写三版 Prompt，**逐版记录效果差异**。这不是"好提示词模板"，是迭代过程本身。

- 方法：单变量迭代、输出原样贴、每版只留 1 个致命问题、四维打分（钩子力/人话度/可用度/像人写的）
- 三版的真实数据：V1 汉字 212 / V2 255 / V3 339，人话度 1 → 5 → 4
- **一个反例**：V3 整体赢了，但"人话度"比 V2 退步了——只看总分就会漏掉
- 完整手册：`index.html`（浏览器打开）

**面试可讲点**：Prompt 迭代不是话术升级，是把自己脑子里的模糊逼成清晰

## 我在这三个项目里反复用的东西

| 原则 | 怎么落地的 |
|---|---|
| **一次只改一个变量** | Prompt 三版，每版只加一类东西；匹配度分析器每次只调一个提示词模块 |
| **可验收 > 好感觉** | 所有硬约束都写成能逐条自查的判据，不让"要好一点"这种话进提示词 |
| **失败版比成功版值钱** | V1 的烂输出、V3 里退步的维度，全部保留在仓库里 |
| **知道自己不做的东西** | 匹配器为什么不做 PDF、为什么不做全自动改写，写在 README 的"已知局限"里 |
