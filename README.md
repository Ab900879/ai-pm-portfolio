## 详细

### 1. `mini-agent` —— 会调用工具的最小 Agent

不依赖 LangChain，纯手写 ReAct 循环。三个工具对应模型的三类硬伤：不知道现在（时间）、算数不准（计算）、不知道公司内部信息（检索）。

- 关键 2 行代码：把工具返回结果当成一条用户消息塞回对话
- 踩坑：工具描述写得太随便 → 模型乱用工具；没设最大步数 → 转了 7 圈
- **面试可讲**：Agent 的效果一半取决于工具描述，这活该产品经理干

### 2. `llm-eval-kit` —— 大模型效果评测

10 条测试用例 + 4 条规则打分 + badcase 按类型聚合。

**最重要的一点：我第一次跑出来的结论是错的。** 模型答"我们公司年假多少天"，正确地说"我无法确认"并给了通用参考，我的评分器却判它 13.3 分——因为要点写的是"公司制度"、模型说的是"公司的具体制度信息"，字面不匹配。

- **面试可讲**：评测失败时，第一反应应该是"我的评分器是不是错了"，而不是"模型不行"

### 3. `prd-to-wireframe` —— PRD 转线框图

读 markdown 格式的 PRD，抽模块，生成单文件 HTML 线框图。异常分支自动抽出来单独标注。

- **最重要取舍：用规则不用大模型。** PRD 结构固定，正则够用且可复现；上模型只是"为了显得高级"
- 附件 `examples/prd-matcher.md` 是一份完整的可读 PRD（含"不做什么"章节、异常分支、验收指标）

### 4. `resume-jd-matcher` —— 简历·岗位匹配度分析器

读取 .docx 简历 + JD，输出逐条对照、3 个致命短板、**可直接照抄的改写句**。

- 三个取舍：不做总分制 / 不做全自动改写（会编造经历）/ 强制结构化 JSON
- 实测：用本人简历跑出 38/100

### 5. `tech-to-human` —— 技术语言 → 人话翻译器

通信背景的差异化优势：别人只能处理科普内容，我能处理真正的技术文档。

- 核心方法论：**只给判据，不给形容词**（"要通俗易懂"无法验收，"禁止出现英文缩写"可以逐条自查）
- 实测三档：同行版 780 字 / 职场版 152 字 / 大白版 108 字 0 术语

### 6. `prompt-lab` —— Prompt 迭代实验

同一素材三版 Prompt + 三版真实输出 + 维度打分。

- V1 汉字 212 / 人话度 1；V2 255 / 5；V3 339 / **4（退步了）**
- **面试可讲**：V3 整体赢，但人话度比 V2 退步——只看总分就会漏掉这件事

## 我在这 6 个项目里反复用的东西

| 原则 | 怎么落地的 |
|---|---|
| **一次只改一个变量** | Prompt 三版每版只加一类东西；评测每次只调一条规则 |
| **可验收 > 好感觉** | 所有硬约束写成能逐条自查的判据 |
| **失败版比成功版值钱** | V1 的烂输出、评测的错误结论、Agent 转 7 圈，全部保留在仓库里 |
| **知道自己不做的东西** | 每个 README 都有"已知局限"，写明为什么不做 |
| **不是所有环节都该上模型** | 线框图用规则不用大模型，评测先用规则不用 LLM-as-Judge |
